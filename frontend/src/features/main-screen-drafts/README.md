# 메인 화면 예시안 담당자 작업 지시서

이 문서를 위에서부터 한 단계씩 진행합니다. 파일 이름은 아래에 적힌 그대로 사용합니다.

## 1. 이 작업의 결과

같은 기능을 서로 다르게 배치한 메인 화면 3~4개를 만들어 팀이 비교할 수 있게 합니다.

실제 지도와 예측 서버는 연결하지 않습니다. 지도처럼 보이는 상자와 가짜 대여소 자료를 사용합니다.

## 2. 작업할 폴더

`frontend/src/features/main-screen-drafts/`

이 폴더 밖의 파일은 수정하지 않습니다. 특히 `frontend/src/App.tsx`는 조장 또는 화면 통합 담당자가 연결합니다.

## 3. 먼저 만들 폴더

`frontend/src/features/main-screen-drafts/drafts/`

아래의 화면 파일 4개를 이 `drafts` 폴더 안에 만듭니다.

## 4. 만들어야 하는 파일

### `MainScreenDraftsPage.tsx`

1안부터 4안까지 한 화면에서 선택하고 비교하게 만드는 파일입니다.

### `MainScreenDraftsPage.css`

예시안 선택 버튼과 비교 화면의 크기, 간격, 작은 화면 모양을 정하는 파일입니다.

### `mockStations.ts`

화면에서 사용할 가짜 대여소 자료를 적는 파일입니다.

대여소 하나마다 다음 값을 넣습니다.

- 대여소 번호
- 대여소 이름
- 현재 자전거 수
- 도착 시 대여 가능성: 높음·보통·낮음
- 걸리는 시간
- 자료 기준시각

### `drafts/Draft1MapFirst.tsx`

1안입니다. 지도를 가장 크게 보여 주고 검색창과 자세한 정보를 지도 위나 아래에 배치합니다.

### `drafts/Draft2MapAndList.tsx`

2안입니다. 지도와 대체 대여소 목록을 한 화면에서 함께 비교하게 만듭니다.

### `drafts/Draft3SearchFirst.tsx`

3안입니다. 출발지와 자전거를 빌릴 장소 입력을 먼저 보여 주고 그다음 지도를 보여 줍니다.

### `drafts/Draft4QuickPrediction.tsx`

4안입니다. 현재 위치와 “몇 분 후” 선택을 가장 먼저 보여 줍니다.

시간이 부족하면 1~3안까지만 만들고 4안은 만들지 못한 이유를 기록합니다.

## 5. 모든 예시안에 넣을 내용

- 지도처럼 보이는 영역
- 주변 대여소와 현재 자전거 수
- 출발지와 자전거를 빌릴 장소 입력
- 도보·대중교통 선택
- 도착시간 예측과 “몇 분 후” 직접 선택
- 대여 가능성 높음·보통·낮음
- 선택한 대여소 자세히 보기
- 가능성이 낮을 때 다른 대여소 최대 5곳
- 자료 기준시각
- 자료 지연과 예측 불가 상태
- 예측 실행 시 로그인 안내

## 6. 작업 시작 명령

PowerShell을 열고 아래 명령을 한 줄씩 입력합니다.

```powershell
cd D:\GitHub\ddarung-flow\frontend
npm install
npm start
```

브라우저에 React 기본 로고 화면이 보이면 준비가 된 것입니다.

## 7. 작업 순서

1. `drafts` 폴더와 위 파일을 정확한 이름으로 만듭니다.
2. `mockStations.ts`에 가짜 대여소 자료 5개 이상을 만듭니다.
3. 1안부터 차례대로 화면을 만듭니다.
4. `MainScreenDraftsPage.tsx`에서 각 안을 선택해 볼 수 있게 합니다.
5. 조장에게 `MainScreenDraftsPage`를 전체 화면에 연결해 달라고 요청합니다.
6. 각 안의 장점 2개와 단점 2개를 Notion 작업 카드에 적습니다.
7. 추천안 하나와 추천 이유를 적습니다.

## 8. 완료 기준

- 3~4안을 한 화면에서 비교할 수 있습니다.
- 각 안의 정보 배치와 사용 순서가 분명히 다릅니다.
- 작은 화면용 모습이 하나 이상 있습니다.
- 정상·낮은 가능성·자료 지연·예측 불가 상태가 예시 중에 보입니다.
- `npm run build`가 성공합니다.
- 담당자가 추천안과 이유를 설명할 수 있습니다.
